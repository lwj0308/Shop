## 二、P0 任务详细设计

### RL-01：Gateway 令牌桶限流优化

**目标**：高频接口从 ZSet 精确滑动窗口改为令牌桶，解决高并发内存/CPU 瓶颈。

**改动文件**：

| 文件 | 操作 | 说明 |
|------|------|------|
| `shop-gateway/src/main/java/com/shop/gateway/config/RateLimitProperties.java` | 修改 | 新增 `algorithm` 字段（sliding-window / token-bucket）和 `capacity` 字段 |
| `shop-gateway/src/main/java/com/shop/gateway/config/RateLimitScriptConfig.java` | 修改 | 新增令牌桶 Lua 脚本 Bean |
| `shop-gateway/src/main/java/com/shop/gateway/filter/RateLimitFilter.java` | 修改 | 按算法类型分发到不同检查逻辑 |
| `shop-gateway/src/main/resources/application.yml` | 修改 | 配置每个规则的算法和参数 |
| `docker/nacos/config/shop-gateway.yml` | 修改 | 同步限流配置 |

**实现步骤**：

1. **扩展配置类** `RateLimitProperties`
   - Rule 新增 `algorithm` 字段（枚举：`sliding-window` / `token-bucket`）
   - Rule 新增 `capacity` 字段（令牌桶桶容量，仅 token-bucket 生效）
   - Rule 新增 `rate` 字段（令牌生成速率，仅 token-bucket 生效）

2. **新增令牌桶 Lua 脚本**
   - 用 Redis Hash 存储状态（`tokens` + `last_refill`）
   - Lua 脚本逻辑：补充令牌 → 判断令牌 → 消耗令牌 → 更新状态
   - 注册为 `DefaultRedisScript<Long>` Bean

3. **改造 RateLimitFilter**
   - 根据 `rule.algorithm` 分发：
     - `sliding-window` → 现有 ZSet 逻辑
     - `token-bucket` → 新增令牌桶逻辑
   - 默认算法：`token-bucket`（高频场景）

4. **更新配置**
   - 认证接口：`algorithm: sliding-window`（低频高精度）
   - 秒杀/下单/商品浏览：`algorithm: token-bucket`（允许突发）
   - 评论接口：`algorithm: sliding-window`（低频高精度）

**验证方式**：
```powershell
# 秒杀接口（令牌桶，rate=3, capacity=5）
# 瞬时发 10 个请求，前 5 个放行（桶容量），后续按速率补充
1..10 | ForEach-Object {
    $code = curl.exe -s -o NUL -w "%{http_code}" "http://localhost:8844/api/seckill/grab/test"
    Write-Host "Request $_ : $code"
}

# 认证接口（ZSet 滑动窗口，IP 5 QPS）
# 1 秒内发 10 个请求，前 5 个放行，后 5 个 429
1..10 | ForEach-Object {
    $code = curl.exe -s -o NUL -w "%{http_code}" "http://localhost:8844/api/user/auth/login"
    Write-Host "Request $_ : $code"
}
```

| `shop-*/src/main/java/.../SentinelFallbackHandler.java` | 新建 | 限流/降级兜底处理 |

**实现步骤**：

1. **父 POM 添加依赖管理**
   ```xml
   <dependency>
       <groupId>com.alibaba.cloud</groupId>
       <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
   </dependency>
   ```

2. **核心服务引入 Sentinel**
   - shop-product / shop-order / shop-seckill 的 pom.xml 添加 Sentinel starter

3. **配置 Sentinel transport**
   ```yaml
   spring:
     cloud:
       sentinel:
         transport:
           dashboard: localhost:8858  # RL-04 部署后启用
           port: 8719
         eager: true
   ```

4. **关键方法加注解**
   ```java
   @Service
   public class StockServiceImpl implements StockService {
       
       @Override
       @SentinelResource(
           value = "stock:deduct",
           blockHandler = "deductBlockHandler",
           fallback = "deductFallback"
       )
       public boolean deduct(Long skuId, Integer quantity, String orderNo) {
           // 原有业务逻辑
       }
       
       // 限流兜底（QPS 超限触发）
       public boolean deductBlockHandler(Long skuId, Integer quantity, String orderNo, BlockException ex) {
           throw new BusinessException("库存服务繁忙，请稍后重试");
       }
       
       // 降级兜底（业务异常触发）
       public boolean deductFallback(Long skuId, Integer quantity, String orderNo, Throwable ex) {
           log.error("库存扣减降级，skuId={}, orderNo={}", skuId, orderNo, ex);
           throw new BusinessException("系统繁忙，请稍后重试");
       }
   }
   ```

5. **硬编码限流规则**（后续 RL-05 迁到 Nacos）
   ```java
   @PostConstruct
   public void initRules() {
       FlowRule rule = new FlowRule("stock:deduct");
       rule.setGrade(RuleConstant.FLOW_GRADE_QPS);
       rule.setCount(1000);  // 1000 QPS
       FlowRuleManager.loadRules(Collections.singletonList(rule));
   }
   ```

**验证方式**：
- 启动服务，访问接口，确认无异常
- 用 JMeter 压测，QPS 超过阈值时返回限流提示


   ```java

       name = "shop-product",
       path = "/product/inner",
       fallbackFactory = ProductFeignFallbackFactory.class
   )
   public interface ProductFeignClient {
       @PostMapping("/stock/deduct")
       Result<Boolean> deductStock(@RequestBody StockDeductDTO dto);
   }
   
   @Component
   @Slf4j
   public class ProductFeignFallbackFactory implements FallbackFactory<ProductFeignClient> {
       @Override
       public ProductFeignClient create(Throwable cause) {
           log.error("商品服务调用降级", cause);
           return new ProductFeignClient() {
               @Override
               public Result<Boolean> deductStock(StockDeductDTO dto) {
                   return Result.fail("商品服务繁忙，请稍后重试");
               }
           };
       }
   }
   ```

**验证方式**：
- 模拟 shop-product 宕机，确认 shop-order 调用时快速返回降级提示，不抛异常

### RL-11：黑白名单机制（IP/用户）

**目标**：黑名单直接拦截，白名单跳过限流，比单纯限流更高效。

**改动文件**：

| 文件 | 操作 | 说明 |
|------|------|------|
| `shop-gateway/src/main/java/.../filter/BlacklistFilter.java` | 新建 | 黑白名单过滤器（Order=-90，在限流前执行）|
| `shop-gateway/src/main/java/.../config/BlacklistConfig.java` | 新建 | 黑白名单配置类 |
| `shop-gateway/src/main/resources/application.yml` | 修改 | 黑白名单初始配置 |
| `docker/nacos/config/shop-gateway.yml` | 修改 | 同步配置 |

**实现步骤**：

1. **新建 BlacklistFilter（Order=-90，在 RateLimitFilter=-80 之前）**
   ```java
   @Component
   @Order(-90)
   public class BlacklistFilter implements GlobalFilter, Ordered {
       
       @Override
       public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
           String ip = getClientIp(exchange);
           String userId = exchange.getRequest().getHeaders().getFirst("X-User-Id");
           
           // 1. 黑名单检查（命中直接 403）
           if (isBlacklisted(ip, userId)) {
               return reject403(exchange);
           }
           
           // 2. 白名单检查（命中跳过限流）
           if (isWhitelisted(ip, userId)) {
               exchange.getAttributes().put("SKIP_RATE_LIMIT", true);
           }
           
           return chain.filter(exchange);
       }
       
       @Override
       public int getOrder() { return -90; }
   }
   ```

2. **RateLimitFilter 检查 SKIP_RATE_LIMIT 标记**
   ```java
   // 在 RateLimitFilter 开头
   if (Boolean.TRUE.equals(exchange.getAttribute("SKIP_RATE_LIMIT"))) {
       return chain.filter(exchange);  // 白名单跳过限流
   }
   ```

3. **黑白名单存储（Redis Set）**
   ```
   IP 黑名单：  SISMEMBER blacklist:ip 1.2.3.4
   用户黑名单： SISMEMBER blacklist:user 1001
   IP 白名单：  SISMEMBER whitelist:ip 10.0.0.1
   用户白名单： SISMEMBER whitelist:user 1001
   ```

4. **自动拉黑策略**
   ```java
   // 触发限流超过 10 次 → 自动拉黑 1 小时
   if (rejectCount.incrementAndGet() > 10) {
       redisTemplate.opsForSet().add("blacklist:ip:" + ip, "1");
       redisTemplate.expire("blacklist:ip:" + ip, 1, TimeUnit.HOURS);
   }
   ```

**验证方式**：
- IP 加入黑名单后请求返回 403
- IP 加入白名单后跳过限流
- 触发限流 10 次后自动拉黑

   ```typescript
   function getIdempotentKey(businessType: string): string {
       return `${businessType}_${userId}_${Date.now()}_${Math.random().toString(36).slice(2)}`;
   }
   
   // 下单请求携带幂等键
   axios.post('/api/order/create', data, {

   });
   ```

2. **后端幂等校验（限流通过后）**
   ```java
   @PostMapping("/create")
   public Result createOrder(@RequestBody OrderCreateDTO dto, 
                              @RequestHeader("X-Idempotent-Key") String idempotentKey) {
       // 1. 限流已通过（Gateway + Sentinel）
       // 2. 幂等校验
       String key = "idempotent:order:" + idempotentKey;
       Boolean isNew = redisTemplate.opsForValue().setIfAbsent(key, "1", 24, TimeUnit.HOURS);
       if (Boolean.FALSE.equals(isNew)) {
           return Result.fail("请勿重复提交");
       }
       // 3. 业务处理
       return orderService.createOrder(dto);
   }
   ```

   ```java
   // 幂等键未消耗，客户端可用相同 key 重试
   ```

   ```typescript
   export function useDebounce(delay = 1000) {
     const loading = ref(false)
     const run = async (fn: () => Promise<void>) => {
       if (loading.value) return
       loading.value = true
       try {
         await fn()
       } finally {
         setTimeout(() => { loading.value = false }, delay)
       }
     }
     return { loading, run }
   }
   ```
