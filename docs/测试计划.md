# Shop 项目测试计划

> 配套文档：[测试方案.md](./测试方案.md)
> 文档目的：将测试方案落地为可执行的任务计划，明确"做什么、谁来做、什么时候做、做到什么程度"。

---

## 一、测试目标

### 1.1 总体目标

| 维度 | 目标 | 验收标准 |
|------|------|---------|
| 功能 | 核心业务流程全部通过测试 | 测试用例通过率 100% |
| 覆盖率 | 后端行覆盖率 ≥ 60%，前端 ≥ 50% | JaCoCo / V8 报告达标 |
| 性能 | 核心接口满足性能指标 | JMeter 压测达标 |
| 稳定 | 24h 稳定性测试无内存泄漏 | 监控无异常 |
| 安全 | 无高危漏洞 | OWASP 扫描通过 |
| 自动化 | 核心场景自动化回归 | CI 流水线全绿 |

### 1.2 阶段目标

- **第一阶段**：补全单元测试，建立测试规范
- **第二阶段**：搭建前端测试基础设施，添加覆盖率
- **第三阶段**：补充集成测试与 E2E 测试
- **第四阶段**：性能测试、安全测试、CI/CD 集成

- 运维部署脚本（除非影响功能）

## 三、测试策略

### 3.1 测试分层与执行频率

| 测试类型 | 执行时机 | 执行频率 | 工具 |
|---------|---------|---------|------|
| 单元测试 | 开发提交前 / CI | 每次提交 | JUnit5 / Vitest |
| 切片测试 | CI | 每次提交 | @WebMvcTest / @vue/test-utils |
| 集成测试 | CI / 每日构建 | 每日 | Testcontainers |
| API 测试 | 发版前 | 每个版本 | Apifox |
| E2E 测试 | 发版前 | 每个版本 | Playwright |
| 性能测试 | 重大版本 | 按需 | JMeter |
| 安全测试 | 重大版本 | 按需 | OWASP ZAP |
| 探索性测试 | 测试阶段 | 按需 | 人工 |

### 3.2 测试用例设计方法

| 方法 | 应用场景 |
|------|---------|
| 等价类划分 | 输入参数验证（手机号、金额、数量） |
| 边界值分析 | 库存边界（0、1、最大值）、分页边界 |
| 因果图 | 促销与优惠券叠加规则、订单状态流转 |
| 错误推测 | 重复请求、并发抢购、网络超时 |
| 场景法 | 完整业务流程（下单 → 支付 → 发货 → 评价） |
| 状态迁移 | 订单状态机、秒杀活动状态机 |

### 3.3 Bug 优先级定义

| 优先级 | 定义 | 响应时间 | 示例 |
|--------|------|---------|------|
| P0 阻塞 | 核心功能不可用 | 立即修复 | 下单失败、支付失败、秒杀超卖 |
| P1 严重 | 重要功能异常 | 24h 内 | 优惠券无法使用、评价提交失败 |
| P2 一般 | 次要功能异常 | 版本内修复 | 列表排序错误、分页异常 |
| P3 轻微 | UI/体验问题 | 排期修复 | 样式错位、文案错误 |

## 四、测试阶段与里程碑

### 4.1 整体阶段划分

```
阶段1: 单元测试补全          阶段2: 前端测试搭建         阶段3: 集成/E2E测试
├─ 后端核心模块单测          ├─ Vitest 基础设施          ├─ Testcontainers 集成测试
├─ JaCoCo 覆盖率             ├─ shared 工具函数测试      ├─ Playwright E2E
└─ 测试规范文档              ├─ 组件测试                 ├─ 契约测试
                             └─ 覆盖率                   └─ API 自动化

阶段4: 非功能测试            阶段5: 持续集成
├─ JMeter 性能压测           ├─ CI/CD 流水线
├─ OWASP 安全扫描            ├─ 质量门禁
├─ 稳定性测试                └─ 自动化回归
└─ 兼容性测试
```

### 4.2 里程碑

| 里程碑 | 内容 | 交付物 |
|--------|------|--------|
| M1 | 后端核心模块单元测试补全 | 单元测试代码、覆盖率报告 |
| M2 | 前端测试基础设施搭建 | Vitest 配置、shared 测试 |
| M3 | 组件测试与覆盖率 | 组件测试代码、覆盖率报告 |
| M4 | 集成测试与 E2E 测试 | Testcontainers 用例、Playwright 用例 |
| M5 | 性能与安全测试 | JMeter 报告、OWASP 报告 |
| M6 | CI/CD 集成完成 | 流水线配置、质量门禁生效 |

> ⚠️ 时间安排：本计划不绑定具体日期，由项目负责人根据团队资源排期。每个里程碑建议预留 20% 缓冲时间应对风险。

## 八、风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| Spring Boot 4.0 新版本测试 API 变更 | 测试代码不兼容 | 中 | 提前验证，查阅 4.0 迁移指南 |
| Testcontainers 在 Windows Docker Desktop 性能差 | 集成测试慢 | 中 | 用 CI 环境（Linux）跑集成测试，本地可选跳过 |
| H2 与 MySQL SQL 方言不兼容 | DAO 测试失败 | 中 | 复杂 SQL 改用 Testcontainers + 真实 MySQL |
| 前端从零搭建测试，团队不熟悉 Vitest | 进度延误 | 高 | 先培训，编写样板测试，参考 shared 模块 |
| E2E 测试环境依赖完整后端 | 测试不稳定 | 高 | 用 MSW mock 接口，或独立 test 环境跑 E2E |
| 秒杀并发测试难复现 | 性能问题难发现 | 中 | JMeter 分布式压测 + Testcontainers 集成测试 |
| 测试数据污染 | 环境脏数据 | 中 | Testcontainers 隔离 + 每用例独立数据 |
| 覆盖率指标导致刷测试 | 测试质量低 | 中 | 代码审查 + 关键场景必测清单 |
